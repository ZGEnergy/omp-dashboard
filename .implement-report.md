# Implement Report: Plan-Approval Host for `write xd://propose` (#121)

## Summary
Implemented dashboard plan-approval host for `write xd://propose` / `xdev.tool === "propose"` using PromptBus protocol (`prompt_request`, `prompt_response`, `prompt_dismiss`) without introducing any new WebSocket events or protocol messages.

## Changes Made
1. **Shared Input-Needed Detection (`packages/shared/src/input-needed-tools.ts` & `types.ts`)**:
   - Extended `isInputNeededTool` to accept `(toolName, args)`.
   - Added `isProposeWrite` helper checking `write` with `path === "xd://propose"` or `xdev.tool === "propose"`.
   - Added `currentToolArgs` field to `DashboardSession`.
   - Documented core architecture gap: `@oh-my-pi` TUI `#approvePlan` continuation is unreachable; answers flow through PromptBus `respond` and host hooks.

2. **Server Status Extraction & Push Classifiers (`packages/server/src/...`)**:
   - `event-status-extraction.ts`: Updated `extractSessionUpdates` to record `currentToolArgs` on `tool_execution_start` and clear on end/start deltas.
   - Updated `isUnreadTrigger`, `event-wiring.ts`, `build-push-payload.ts`, and `push-trigger-classifier.ts` to pass `currentToolArgs` to `isInputNeededTool`.

3. **Extension Bridge Interception (`packages/extension/src/propose-tool.ts` & `bridge.ts`)**:
   - Implemented `registerProposeTool` intercepting `write xd://propose` and `propose` calls.
   - Extracts plan title and path (`local://${planPath}`).
   - Dispatches PromptBus `select` prompt BEFORE tool execution finishes with `metadata.toolCallId`.
   - On `"Approve and execute"`, dispatches `onPlanApproved` and `pi.events.emit("plan:approved", ...)`.
   - On `"Refine plan"`, prompts for input feedback and retains session in plan mode.
   - On `"Reject"` or cancel, completes tool with rejection notice and retains session in plan mode.

4. **Client UI & Callsites (`packages/client/src/...`)**:
   - Updated all client `isInputNeededTool` callsites across ChatView, CollapsedToolGroup, FolderNeedsYouPill, OpenSpecBoardView, SessionCard, ToolBurstGroup, ToolCallStep, and session-status-visuals to pass tool `args` / `currentToolArgs`.
